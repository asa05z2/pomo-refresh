# 集中時間提案ロジック説明書

## 1. 目的

PomoRefreshの集中時間提案機能は、ユーザーが無理に長いタイマーを使い続けることを避け、実際に集中できた時間に近い短いモードを提案するための機能です。

たとえば、25分モードを選んでいても15〜20分ほどで「ちょっと疲れた」を押すことが続いた場合、次回から15分のショートモードを提案します。

この機能は集中力の優劣を評価するものではありません。ユーザーの最近の状態に合わせ、完了しやすい時間へ調整することを目的としています。

## 2. 使用するデータ

集中セッション終了時に、次の形式で履歴をLocalStorageへ保存します。

```js
{
  modeId: "classic",
  plannedMinutes: 25,
  focusedSeconds: 1080,
  outcome: "tired",
  endedAt: "2026-08-07T00:00:00.000Z"
}
```

| フィールド | 内容 |
| --- | --- |
| `modeId` | セッションで選択していたモードID |
| `plannedMinutes` | 予定していた集中時間（分） |
| `focusedSeconds` | 実際にタイマーが進んだ時間（秒） |
| `outcome` | 完了は `completed`、途中休憩は `tired` |
| `endedAt` | セッション終了日時（ISO 8601形式） |

保存先のキーは `pomorefresh:sessionHistory` です。端末内に直近20件だけを保存し、サーバーへの送信は行いません。

一時停止中の時間は `focusedSeconds` に含みません。タイマーのリセットだけを行った場合は、完了または途中休憩として扱わず、履歴にも保存しません。

「ちょっと疲れた」を押した時点で残り時間が予定時間の10%以下なら、ほぼ最後まで集中できたセッションとして `completed` を記録します。10%ちょうども完了に含みます。実際に集中した秒数は切り上げず、そのまま `focusedSeconds` に保存します。

```text
25分モード: 残り2分30秒以下なら完了
50分モード: 残り5分以下なら完了
90分モード: 残り9分以下なら完了
```

## 3. 提案の判定手順

判定対象は、現在選択しているモードと同じモードの直近5件です。

1. 全履歴から現在の `modeId` と一致する履歴だけを抽出する。
2. 抽出結果の新しい方から最大5件を使用する。
3. 履歴が3件未満なら提案しない。
4. 残り10%以下で押された「ちょっと疲れた」は完了扱いとし、それ以外で `outcome` が `tired` の有効な履歴を数える。
5. 途中休憩が3件未満、または対象履歴の60%未満なら提案しない。
6. 途中休憩までの集中時間を分へ変換し、中央値を求める。
7. 現在より短く、中央値以下で最も長いモードを提案する。
8. 中央値より短いモードがない場合は、現在より短い最短モードを提案する。
9. 現在がすでに最短モードなら提案しない。

60%の判定には境界値を含みます。直近5件中3件が途中休憩の場合は、提案の対象です。

## 4. 中央値を使う理由

平均値は、極端に短いまたは長い1回のセッションに影響されやすいため使用しません。中央値を使うことで、最近の典型的な集中時間を比較的安定して求められます。

奇数件の場合は中央の値、偶数件の場合は中央2件の平均を使用します。

```text
15分、18分、20分 → 中央値 18分
12分、16分、18分、22分 → 中央値 17分
```

UIへ表示する時間は、求めた中央値を四捨五入し、最低1分として表示します。

## 5. 判定例

### 25分から15分を提案するケース

現在のモードが25分で、同一モードの履歴が次の場合を考えます。

| 結果 | 集中時間 |
| --- | ---: |
| 途中休憩 | 15分 |
| 途中休憩 | 18分 |
| 途中休憩 | 20分 |

- 履歴数: 3件
- 途中休憩: 3件、100%
- 中央値: 18分
- 18分以下で最も長いモード: 15分

結果として、ショート（15分）を提案します。

### 50分から25分を提案するケース

50分モードで28分、30分、34分に途中休憩した場合、中央値は30分です。30分以下で最も長い既存モードは25分なので、クラシック（25分）を提案します。

### 提案しないケース

- 履歴が2件しかない。
- 直近5件の途中休憩が2件だけで、割合が40%である。
- 以前は途中休憩が多かったが、直近5件はすべて完了している。
- 3分の最短モードを選択している。

## 6. 戻り値

提案がある場合、`calculateRecommendation` は次のオブジェクトを返します。

```js
{
  mode: { id: "short", name: "ショート", focus: 15 },
  typicalMinutes: 18,
  sampleSize: 3
}
```

| フィールド | 内容 |
| --- | --- |
| `mode` | 提案するモード |
| `typicalMinutes` | 途中休憩までの集中時間の中央値（表示用の分） |
| `sampleSize` | 中央値の計算に使用した途中休憩件数 |

提案条件を満たさない場合は `null` を返します。

## 7. 画面への反映

提案がある場合、モード一覧の上に「あなたへのおすすめ」カードを表示します。カードには提案モード、最近の典型的な集中時間、判定に使用した件数を表示します。

「ショートに切り替える」などのボタンを押すと、通常のモード選択と同じ処理でモードを変更し、前回選択モードとしてLocalStorageへ保存します。提案を無視して現在のモードを使い続けることもできます。

## 8. 実装箇所

- 判定ロジック: `recommendation.js`
- 履歴の記録とUI連携: `app.js`
- 提案カード: `index.html`、`styles.css`
- 自動テスト: `tests/recommendation.test.js`

判定関数は画面やLocalStorageに直接依存しない純粋関数です。同じ引数には常に同じ結果を返すため、単体テストで条件を確認できます。

## 9. テスト方法

プロジェクトのルートで次を実行します。

```bash
node --test
```

テストでは、代表例のほかに履歴件数、60%の境界、直近5件、モードの混在、不正値、最短モードを検証しています。

## 10. 現在の制約

- 提案は短いモードへの変更だけを対象とし、長いモードへの変更は提案しません。現在の最短モードは3分です。
- ブラウザや端末が変わると履歴は共有されません。
- ブラウザのサイトデータを削除すると履歴も消去されます。
- モード構成を変更する場合は、保存済みの `modeId` との互換性を考慮する必要があります。
- 集中時間は自己申告ではなく、タイマーが実際に進んだ時間から算出します。

判定条件を変更する場合は、仕様書、実装、テストの3か所を同時に更新してください。
